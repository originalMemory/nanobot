# Spec: active-memory-topic-recall

## Why
- 3257 篇日记下搜索约 500ms，可继续 use 文件检索。
- 当前最近 5 篇截断丢失高频主题的长期脉络，AND 结果也可能被近期 OR 结果挤出。
- 高频主题需要可复用摘要，生成过程不能阻塞当前聊天。

## Scope
- 每个关键词并行搜索一次；按关键词覆盖数、概要命中、日期、正文频次排序。
- 单轮原始日记上限从 5 调为 10；空片段继续向后补位。
- 高频主题无摘要卡时 use `6` 篇近期结果 + 最多 `4` 篇时间分层历史结果。
- 高频主题摘要卡由内部后台任务按需生成并持久化；不向 Agent 暴露工具。
- 摘要卡 use YAML `概要` 生成长期阶段，use topic 命中行 ±1 行正文证据生成实体关系。
- 主题卡区分 aliases 与 related_entities；关联实体记录关系类型和来源日期。
- 候选或源文件变化时后台单飞更新；更新完成前继续 use 旧卡。
- 不引入向量库、FTS、外部数据库或前台同步总结。

## Apply Notes
- 长期主题阈值：命中不少于 `20` 篇、覆盖至少 `3` 个自然月、首尾跨度至少 `90` 天。
- 原始结果最多 `10`；不另设 Active Memory 总字数预算。
- 无可用卡时，历史代表按时间桶选取同桶最高排名结果，不随机抽样。
- 摘要任务直接复用当前主 provider/model，`tools=None`；不进入 Agent loop，不新增模型配置。
- 摘要输入不分批、不截断；use 主模型完整上下文提升主题时间线精度。
- 主模型生成 durable topic、aliases、related_entities 和主题时间线；related entity 必须出现在概要或正文证据。
- 缓存目录：`workspace/memory/active_memory_topics/`；文件名 use topic hash，JSON 原子替换。
- 指纹覆盖候选相对路径、mtime、size；变化触发后台重建。
- 前台不等待摘要任务；搜索与注入路径保持可独立降级。
- 后台摘要 use AgentLoop tracked background task 独立执行；前台不等待、不取消。
- 卡片名称 use casefold/token 匹配；实体来源日期按包含该实体的概要或正文证据计算。
