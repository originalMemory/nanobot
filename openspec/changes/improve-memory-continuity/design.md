## Goals / Non-Goals

**Goals:**

1. 能准确接住“这件事后来如何”“为什么我在意”，并区分事实、过去状态与推测。
2. 原始日记召回不被副本、附件或序号污染；卡片关系可追溯。
3. 独立主题能建卡，既有卡只为自己的有效新证据更新。
4. 画像与主题摘要同时保留稳定认识、最新状态与必要转折，迁移不丢原始材料。
5. 有可重复的质量对照，而非只统计注入数量。

**Non-Goals:**

- 不引入向量数据库、知识图谱、额外常驻近期摘要、跨会话实体状态服务。
- 不改统一会话、压缩算法、Dream 两小时调度、主动问候频率和前端。
- 不自动搜索全部历史对话、不重写所有日记、不批量重训小模型。
- 不把一次情绪、助手建议或关系推测沉淀为永久用户事实。

## Decisions

### 1. 继续使用现有分层，让每层解决自己的问题

| 层 | 负责 | 本次调整 |
|---|---|---|
| AGENTS | 工作区规则与工具入口 | 删除与 SOUL 重复的表达细则；写清何时查日记/原始会话 |
| SOUL | 人格、语气、关系边界 | 保留原有声音；补证据不足不推断动机、自然延续而不强行翻旧事 |
| USER | 稳定画像、偏好原因、少量重要当前状态 | 当前状态带绝对日期；变化时更新，并给重要转折留短引用 |
| MEMORY | 项目与运行环境的跨会话背景 | 修正过期机制描述；不混入逐日生活流水账 |
| 当前会话及压缩摘要 | 最近互动与尚在推进的事情 | 本次不加新注入层；检查真实发送范围，归档提示词保留必要后续 |
| 日记/原始会话归档 | 事件证据与原话 | 保持完整；改善检索，不以画像或主题卡代替原始记录 |
| 主题卡 | 跨日/跨年的阶段、原因与转折 | 校准关系、独立生成、按证据刷新 |

替代方案：另加近期摘要文件会与现有会话、USER 当前状态、压缩摘要重叠。暂不采用，只有质量回放证明仍缺近期连续性时另提变更。

### 2. 先治理提词，再有限补全指代

首批实现不改变 1.7B 的输出格式，减少对既有微调分布的冲击：

- 输入剥离 runtime/reference、附件路径与文件名包装；不对图片内容做无依据猜测。
- 输出大小写归一去重、最多 5 个词；无来源词丢弃，路径/附件名/纯序号不参与检索。已知规范名和别名如 `115` 保留，不能粗暴禁用全部数字。
- 提词不稳定时安静跳过，主模型仍能使用原会话与工具；不将“无”自动判为漏召回。
- `rg/grep` 参数明确使用字面搜索及选项终止，用户文本不能变成命令选项。

第二批在同一回放集上加入有限对话辅助，默认试验窗口为最近 3 个用户轮次及对应非工具最终回复，最多 2000 字；排除推理、工具输出、历史 Active Memory 注入及定时任务文本。当前消息优先。

- 仅允许从当前消息或该窗口中有明确指代依据的原文抽词，记录词来自当前消息还是近期对话。
- “那个终于到了”在近文只有一个明确订购物时可补全；多个候选时不猜。
- “收藏第 3 张”是对当前生成结果的操作，不因旧话题存在而搜索日记。
- 新窗口方案若在真实 1.7B 上增加误召回或突破原 6 秒超时预算，不默认启用；先保留输入输出治理成果。重训或换模型独立评估。

不采用同步额外主模型检索规划调用：其延迟与成本没有当前证据支持。无法自动解析的回指仍由主模型按需调用已有 `session_search` / `diary_search`。

### 3. 正式日记来源与片段一致

- 自动召回、手动 `diary_search`、主题计数和主题摘要输入使用同一正式来源规则：跳过 `.sync-conflict-*`，不改动磁盘原件。
- 按正式日记身份去重；本库每日一篇，日期重复但有多个非冲突正式文件时保留可区分的文档身份，不武断按日期删除独立笔记。长期门槛按独立日记日期计数，避免同一天重复证据抬高频率。
- 实现先在现有日记搜索模块放小型纯函数供两条路径复用，不新建通用检索框架。顺手发现的其他手动搜索问题另报，不扩大范围。
- 日期优先使用合法日记日期；空概要必须是空值，不能因跨行空白匹配吞入“心情”等下一个字段。
- 片段从相关正文段落取证，过滤 YAML、天气 API 数据、导航和引言；全日概要仅在与查询相关时作为补充，不挤掉关键正文。
- 保持最多 10 条结果，单条正文先以 400 字为上限；先按词覆盖及相关性分层，再在同层兼顾近期、转折或跨期代表。有卡时也不直接用全体候选日期倒序覆盖相关性。
- 规范日期/源路径随片段保留，主模型可通过已有文件工具读取全文；片段不承担完整回答所有历史问题的职责。

### 4. 移除未知词的全库共现推断，恢复独立主题发现

保留 `topic > alias > confirmed entity` 匹配。删除 `_infer_parent_topic_card` 自动扫描旧卡并提交陌生词关系判定的流程。

无卡时，每个通过正式来源门槛的候选独立进行资格判断；已有弱关系或 `related_topics` 不阻断独立主题。送审门槛采用至少 5 个独立日记日期，不限制跨度；达到门槛只进入模型审核，不为所有一次性事件建卡。

- 新卡生成时从该主题自己的正文证据提取专属实体。
- 新角色尚未进卡时先返回其原始日记；下一次主题本身被查询且证据变化后，正常刷新可发现该角色。
- `related_topics` 没有运行用途，按用户确认删除；不生成、不保存、不参与检索。
- 同时出现多个独立候选时，按查询相关性和证据质量稳定排序；每轮最多安排一个新卡任务，避免后台扇出。

代价：未知角色首次出现不会立即找到父主题卡；好处是消除“相亲→游戏”“游戏→菜品”这类昂贵猜测。原始日记召回仍可用。

### 5. 关系必须能解释“为何这次应带入父主题”

卡片 schema 从当前 v5 升到下一版本（实施前核对版本）；沿用 JSON 文件，不增加关系数据库。

- aliases 仅同义名，不接受随意扩写、拼接名或另一个独立主题。
- related_entities 必须有主题正文中能支持专属关系的具体片段与源文档定位；“名字在源文本出现过”只是必要条件。
- 助手、用户、通用商店、支付平台、食材、跨作品机制不能仅因参与过事件成为从属实体。禁止用人物/组织枚举值伪装从属关系。
- 查询独立商店或助手名称不能继承一道菜的历史；查询专属游戏角色可以继承所属作品历史。
- 候选关系含糊或多父主题时不硬选，返回原文。旧版本关系未经新契约复核前不用于前台继承。
- 不依赖代码判断所有语义；生成提示词给正反例，结构层检查来源与类型，脱敏回放检验实际关系质量。

### 6. 卡片刷新围绕有效证据，失败有退路

- fingerprint 基于规范相对来源身份、日期与该主题相关正文/概要内容，而非整文件 mtime、天气块或本地绝对路径。
- 引入 source completeness 结果：完整扫描且能读完正式证据才允许替换旧卡；读失败保留旧卡，不把故障当成历史缩短。
- 完整扫描后，纠正、删除或去重导致 source_count 变少仍允许更新。移除“数量减少一律拒写”的保护，改保护来源完整性。旧卡可能已有重复计数，不应由它永久阻止修复。
- 生成仍在回复结束后后台执行，保留原子替换与单飞。无证据变化不调用模型。
- 资格结果缓存绑定规则版本、证据 fingerprint 和实际模型卡片索引的 fingerprint；证据实质变化或显式修订规则时才重评。只有格式/读取/服务故障不能保存为语义拒绝。
- 同一主题+证据版本的失败设 1 小时重试冷却；下次被查询时再尝试，不新增定时服务。失败不会改变前台模型 fallback 状态。
- 暂不按当前对话全量重写所有卡，也不依据旧拒绝名单继续做弱共现分类。

### 7. 归档和 Dream 保存变化，不制造固定人格结论

Consolidator 保留现有主体区分，再补两类信息：

- 稳定事实：偏好、明确决定、适用边界与用户亲述原因。
- 对后续对话重要的事件：绝对日期、已确认发生的事、当前状态、尚未解决的后续；不能仅因不到“两周有效”而一律跳过。

不要求每条聊天都归档，不把工具流水压成生活经历；没有重要内容仍可输出 nothing。摘要优先保留用户关心的未结事项及纠正，不因工具输出长而完全淹没。

Dream 的路由保持现状；事件详情仍主要在日记和 history，只有重要当前状态在 USER 对应领域用一两句保留：

- 相对日期按原消息时间解析；归档执行日不是事件日，无法解析则注明未知，不猜。
- 区分“事实纠正”与“态度随时间变化”。前者替换错误当前事实；后者允许“过去 A → 后来 B，因为 C”，保留有意义的转折。
- 临时计划关闭后退出“当前”描述；有长期解释价值的经历保留带日期的短述或来源。
- “截至某日仍在考虑”不可变成永久偏好；助手建议不自动升级为用户已同意的安排。
- 推测性心理解释保持来源和不确定性，不把模型反复复述算成多次用户确认。
- 不把主题卡全文塞进 Dream。画像与卡片先通过相同来源/时间原则一致维护；初次迁移核对交集，后续私人验收抽查分歧。

替代方案：让 Dream 每次扫描所有卡、让卡反向写画像，会引入第二条自动事实传播链和自我强化。本次不做。

### 8. 回复提示词只补必要行为

现有 SOUL/AGENTS 已包含充分的自然陪伴要求，不继续堆同义指令。合并重复后，集中保留：

> 与当前表达直接相关时，结合已知经历和最新状态自然回应。需要但缺少历史细节时，查日记或原始会话；无法确认就保留未知。不要把旧状态说成现在，不根据当前时刻推断通知时间或他人动机。无需每轮展示“我记得”，也无需每轮主动追问。

不增加固定安慰模板；评测同时保留“已能自然延续”的正例，避免为了召回而把自然聊天改成报告。

### 9. 可解释日志和质量回放

沿用 JSONL 日志，不建仪表盘：每条记录带 timestamp、规则版本、一次检索的关联 ID；记录关键词来源、过滤原因、正式候选数、去重数、卡片匹配方式、生成原因、证据指纹和明确 skip/error 原因。日志不新增整段上下文或完整证据原文。

检查实际发给 provider 的历史消息范围/数量、工具占比和摘要存在性：优先用现有诊断输出和测试 spy；若缺失，只加必要聚合字段，不记录私人正文。NAS 没有对应配置和请求证据前，不改消息上限或压缩策略。

验收分开衡量：

1. 检索是否正确：应命中的历史、允许的父卡、不应注入的内容。
2. 回复是否受益：自然接续、最新状态准确、无编造因果、不强行翻旧事。
3. 成本是否合理：每主题有意义证据变化次数与生成次数、重复失败次数、前台延迟。

固定 20 个脱敏情景回归，覆盖显式实体、回指、跨日进展、状态修正、错误关系、操作消息和无关聊天；其中涉及模型判断的样例运行三次并记录波动，不把单次好结果当保证。硬负例必须全部通过；私人 A/B 至少 16/20 场景同时满足历史/状态准确和表达自然，且不得编造关键人物关系或事件。该数字是拟定验收门槛，不是现有成绩。零关键错误优先于平均分。

## Risks / Trade-offs

- [微调小模型不适应新增近期上下文] → 输入输出治理先落地；第二批窗口在同一模型上对照，失败不默认开启，不临时叠主模型调用。
- [收紧关系导致首次召回减少] → 保留原始日记和主动 session_search；用专属角色正例检测是否过严。
- [去重后来源数下降阻止刷新] → 用完整扫描替代数量单调规则；未完整扫描继续使用旧摘要并标记待更新。
- [时间标注让 USER 变成流水账] → 只在现有领域保留重要当前状态，不加全量近期清单；已结束普通事项退出常驻。
- [从旧卡/助手总结重复学习推测] → 原始证据为准；日期、主体与不确定性不能被二次摘要抹掉。
- [真实数据泄入公开源码] → 迁移草稿、diff、回放输入输出均留在私人目录；仓库只保留脱敏例子和方案。
- [只优化日志数字，聊天仍生硬] → 检索与回复分开验收，比较真实正例，不要求每次调用记忆。

## Migration Plan

### A. 先建立基线和离线候选

1. 保存下载快照与哈希，读取 NAS 当前版本/实际配置并确认运行代码版本；所有引用都带各自截止日期。
2. 私人目录生成 before/after 草稿与逐项变更清单；原文不进源码。
3. 跑旧/新检索回放及关系正反例；此时不触碰运行目录。

### B. 现有文件逐项调整

| 文件/数据 | 具体调整 | 保留与复核 |
|---|---|---|
| AGENTS | 表达细则收束为指向 SOUL；日记和 session_search 各自触发场景；统一普通聊天的 Dream 管理边界 | 不删工作区权限、安全与用户明确规则；不把下载文件当本仓库指令 |
| SOUL | 保留人格和关系声音，合并重复表达约束，加入未知事实不补全 | 不虚构共同经历，不机械去掉用户主动设定 |
| USER | 对当前健康/待购/借款/阶段性游戏状态加日期，核对后续；把稳定偏好与临时状态分句；心理推断保留来源 | 借款不得无证据标已还，计划不得自动标已完成；不推断新的医疗或财务结论 |
| MEMORY | 核对“自动注入近 7 天日记概要”“1.7B 生成摘要”等机制陈述及过期运行状态；有证据才改为现状 | 1.7B 提词、主模型后台建卡职责写清；运行时未验证的 provider/重启状态标待核实 |
| 游戏主题卡 | 保留重要阶段与当前最新态度，去重正式来源，复核专属实体 | 不用 USER 的短结论覆盖更完整的真实事件变化 |
| 菜品主题卡 | 删除助手/商店/通用食材触发父卡的关系，保留菜品体验与用户确认的做法演变 | 供应商或食材可留在有证据的正文里，不作专属实体 |
| 网盘主题卡 | 校正数值别名的来源命中；将仅有通用挂载工具证据的段落标为未确认目标或移出本主题 | 保留已经确认的网盘事件；不能用“工具相关”证明每次上传都到同一服务 |
| decisions / rejected_relations | 旧缓存备份；无效弱共现名单不再驱动模型请求；按新版本契约重评必要项 | 不对所有拒绝项立即发起模型调用；有价值的审计保留在备份 |
| 原日记/会话/history/cursor | 只读 | 不删除冲突原件、不改原话、不回退 Dream 游标 |

涉及私人具体条目的替换原文在实施时随证据生成可审阅 diff。本方案不根据旧快照编写已经过时的最终替换值。

### C. 应用与回滚

1. 实施已获授权时，先完成候选与验证再应用。若用户届时只授权离线整理，则停在离线产物，不部署。
2. 正式应用前重新读取并比对当前文件哈希；发生新写入时重新合并，不用下载快照覆盖。
3. 临时串行化 Dream 和卡片写入与迁移，备份实际被替换的四文件和卡缓存；不额外扩大写入范围。
4. 代码/提示词与数据迁移按依赖顺序切换；旧卡摘要可降级使用，旧版关系不能继续触发继承。单文件原子替换后读回核验，多文件用清单检查完整性。
5. 只对现有三张卡及本次通过资格的少量主题按需重建，不全库重算。后续回放验收后再恢复后台整理。
6. 迁移失败恢复本次修改文件及相应代码版本；回滚前核对是否有迁移后的新写入，有则合并恢复而非覆盖。history、会话、日记、Dream 游标不参与回滚。Git 提交仍须用户明确要求。

### D. 实施顺序

- 第一批：基线、提词治理、正式来源去重、删除弱共现路径、专属关系与刷新机制。
- 第二批：片段相关性、有限指代上下文、归档/Dream 提示词、私人文件迁移草稿。
- 第三批：完整回放、真实模型 A/B、应用获授权的迁移、部署后质量验证。

### 最终实现与实测决定

- 保留稳定单消息提示词，程序校验过滤附件、序号、泛图片词与明确动作词；已知数字服务别名只在业务语境补回，数值测量不作实体。
- 单消息初版 15/20、近期上下文 12/20；最终单消息加校验 17/20，附加三个挑战全过。每个实测情景三次；纯代词回指不猜，不接入近期上下文实验。
- 本地相关测试 218 项、真实检索回放20项通过。主聊天模型自然回复评分仍待 NAS 上验证，不用检索分数替代。

### 用户确认的字段精简

- 卡片 schema v7：实体在生成时仍用 path/quote 校验，落盘只保留 name、relation、sources（相对路径）；不保存整段引用、重复 source_dates 或 exclusive 标志。
- 顶层 date_range 从 sources 去重排序后取首尾；source_count 不持久化。source_files 保留文档定位，不参与召回决策。
- 删除废弃的 rejected_relations 与一次性 migration_note，后者放离线包 README。related_topics 也按用户后续确认删除。
- 专属实体仍由主题生成时的语义判断与证据校验建立；检索按主题名、别名、已确认实体匹配，不恢复同日共现。

### 后续范围确认：移除平级关系

related_topics 没有实际使用者，删除生成提示、解析保存和交付卡字段；旧字段重建时清除。建卡门槛当前仍是20个独立日期且跨度90天，本轮只评估放宽方案，不擅自调整，也未实现“带已有卡片索引进行归属判断”。

### 归属审核与可重评的本次不保存（已获实施授权）

- 5个独立日期送审，取消90天门槛。索引由现有字段直接组装：topic、aliases、已确认entities名称、summary前300字；不增加持久化索引文件。
- 主模型一次审核给 alias/entity/new/no_save。别名或专属实体校验 path/quote 后只补名称映射与必要来源；不保存重复引用、不覆盖父卡摘要。
- no_save 统一表示“本次不保存”，证据不足和价值不足仅在reason中说明。决策缓存升级v3，绑定候选证据、索引和规则版本；执行错误只进入独立重试冷却。
- 同一hook的后台写卡串行，防止不同候选覆盖同一父卡。审核完成前重核索引和来源；完整重建写入前还核对父卡快照，避免覆盖其他更新。
- 下载包卡片格式仍是v7，无需因为门槛变化重写现有卡片。旧v1/v2判定缓存自动失效，运行时按需重评，不批量调用模型。

### Review 四项修复

- 当前版本确认映射作为重建基线，漏返不删除；需要撤销时使用有引用证据的临时mapping_removals，既不落盘也不恢复永久拒绝名单。
- 指向旧父卡的候选先触发完整来源升级，再使用更新索引重新审核，最多额外一轮；失败保留旧数据，不报关联成功。
- 单个文件无法读取仅阻止写卡，不清空健康文件的原始召回。
- 手动搜索在日期/正文过滤后累计有效条数；准备OR候选以供过滤后的补位。
