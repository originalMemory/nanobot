## Context

nanobot 当前已经有 THA 桌宠链路：后端配置 `THAConfig`、`/api/settings` 设置入口、`/ws/tha` 渲染通道、`/ws/tha-events` 音频/标签事件、独立 `tha.html` 页面和 Electron 透明窗口。THA 的模型形态是固定文件，优先读 nanobot 数据目录，不能管理多个模型。

PSB/E-mote 桌宠来自 `/Users/illusion/dev/self/gal-char-anim` 的 `apps/emote-viewer` 验证实现：浏览器侧加载 E-mote WebGL SDK，直接读取原始 `.psb` / `.emtbytes` 文件，管理主 timeline、diff timeline、face 变量、fade 变量、鼠标脸部跟随，并通过 Web Audio 音量分析驱动 `face_talk`。用户上传的模型资产仅为 PSB 二进制文件，不是 FreeMote 反编译后的 JSON + 贴图目录。渲染逻辑适合在 Electron 本地运行，但模型资产应由 nanobot 服务端统一保存和解析，避免多设备使用时到处复制模型。

## Goals / Non-Goals

**Goals:**

- 新增统一 `deskPet.tha` 与 `deskPet.psb` 配置结构，不要求兼容或迁移旧顶层 `tha` 配置。
- 在服务端支持多个 PSB 模型、当前选中模型、模型新增/删除/重扫和元数据持久化，Electron 提供上传入口。
- PSB 桌宠以独立透明窗口展示，可自动启动、临时关闭、永久关闭、拖拽、缩放和追踪全屏鼠标位置。
- 模型新增时解析可用 timeline、表情、face、fade、口型变量，并保存中文展示文案。
- 给 AI 注入当前选中 PSB 的可用标签说明，前端解析回复标签并驱动桌宠状态。
- 复用 THA 的“桌宠窗口本地播放音频并分析口型”策略。

**Non-Goals:**

- 不把用户 PSB 模型默认打包进 nanobot wheel。
- 不实现 PSB 编辑器、模型训练或自动从 win/v4 转 ems/v3 的完整转换管线。
- 不替换 THA 远端渲染链路；THA 与 PSB 在统一配置下并存。
- 不要求浏览器版 WebUI 独立展示 PSB 桌宠；本期目标是 Electron 桌面能力。
- 不实现 PSB 自定义别名；常用组合别名作为后续能力。

## Decisions

### D1: 配置结构使用统一 `deskPet`

**选择**：新增 `deskPet` 顶层配置，结构上包含 `tha` 和 `psb` 两个子项。本变更不实现旧顶层 `tha` 配置迁移；实施时直接以新结构为目标。

**理由**：THA 和 PSB 都是桌宠能力，用户配置需要统一展示；继续扩展顶层 `tha` 会让 PSB 变成异类。当前需求允许不考虑旧配置迁移，因此可以减少兼容层和双写复杂度。

**替代方案**：新增顶层 `psb`，保留顶层 `tha`。实现更快，但设置页会长期存在两个入口，后续再加其他桌宠类型时会继续扩散。

### D2: PSB 模型默认存放在服务端模型仓库

**选择**：PSB 模型资产放在固定目录 `<nanobot-data>/desk_pets/psb/`，用户直接将 `.psb` / `.emtbytes` 放入该目录；gateway 启动时自动扫描并为新文件生成 sidecar 元数据（`<文件名>.meta.json`）。服务端负责头信息兼容性检查、翻译和元数据持久化。完整 timeline/face/fade 能力摘要由 PSB 运行时加载后回传或重扫补齐。Electron 渲染 PSB 桌宠时通过服务端资源 URL 读取当前模型。

**理由**：PSB 是用户可替换资产，但跨平台使用时“每台 Electron 客户端各复制一份”体验很差。服务端统一保存后，macOS/Windows/Linux Electron 客户端只要连接同一个 gateway 就能复用模型、元数据、中文翻译和当前选中状态。Electron 仍负责本地文件选择和桌宠展示，不承担模型仓库职责。

**替代方案**：Electron `userData` 本地存模型。优点是实现简单、完全离线；缺点是每个客户端都要重新导入、重新解析和重新翻译，且当前选中模型无法跨设备共享。

### D3: 模型元数据在新增/重扫时解析并缓存

**选择**：新增模型时由服务端读取已上传的 PSB/emtbytes 文件，先做头信息与兼容性检查并生成 `PsbModelMetadata` 基础字段：模型 id、名称、服务端资源路径、格式、兼容性、PSB 版本、主文件名和解析/翻译状态。timeline、expression、face、fade、口型变量等运行时能力摘要由 PSB 窗口首次加载或用户触发重扫时回传并持久化。

**理由**：设置页应直接展示中文配置项，不应每个 Electron 客户端各自扫描和翻译日文描述。服务端缓存还能为 AI prompt 注入提供稳定、短小的能力摘要。

**替代方案**：运行时每次加载模型时解析。实现少一点持久化，但设置页慢、翻译结果不稳定，也不利于离线展示。

### D4: 翻译采用可复用的模型描述翻译服务，结果落盘

**选择**：服务端模型解析阶段收集日文 label/description/hint，并调用 nanobot 当前配置的 LLM 翻译为中文；翻译失败时保留原文并记录 `translationStatus`，允许用户稍后重试。

**理由**：日文描述来自模型元数据，只有新增/重扫时需要翻译。落盘后所有客户端设置页都可复用同一份中文文案，也避免反复消耗 token。

**替代方案**：前端内置词典。可覆盖常见 `怒/笑/通常`，但无法处理角色自定义 fade/face 描述。

### D5: PSB 桌宠窗口使用独立 renderer 页面和 IPC

**选择**：Electron 主进程创建 `psb` 透明置顶 BrowserWindow，加载专用 renderer 页面；主进程负责窗口生命周期、位置/大小持久化、全屏鼠标坐标采集。renderer 负责 E-mote WebGL SDK、从服务端资源加载模型、绘制、状态切换和音频口型。

**理由**：PSB 渲染是桌面能力，不应进入主聊天视图。独立窗口也便于鼠标穿透、自动隐藏控制列和临时关闭；模型存储和解析放服务端后，Electron 多端展示能共享同一模型状态。

**替代方案**：把 PSB 嵌入主 Electron React 视图。实现配置联动更简单，但不符合“独立桌宠”和全屏鼠标追踪需求。

### D6: 标签协议由桌宠类型协商

**选择**：PSB 启用后，前端/后端根据当前选中模型元数据注入 prompt，说明允许标签：

- `<psb:timeline name="..." />`：播放非循环或循环 timeline。
- `<psb:expression name="..." />`：应用表达预设或 diff timeline。
- `<psb:face var="..." value="..." />`：设置 face 变量。
- `<psb:fade var="..." value="..." />`：设置 fade 变量。

前端解析标签后转发给 PSB 窗口；是否在聊天回复中保留原始标签由配置控制。

**理由**：PSB 能力是模型相关的，不能写死固定标签全集。带命名空间的标签可避免与 THA 的 `<happy>` 等旧标签冲突，也能在回复可见性上单独控制。

**替代方案**：沿用 THA 的短标签。对用户友好，但无法表达 face/fade 变量和值，也容易跨模型失效。

### D7: 状态恢复分为 timeline 结束和流式结束

**选择**：非循环 timeline 由 PSB 窗口根据 timeline 时长或播放结束事件自动切回配置的初始循环 timeline。expression/face/fade 等状态在本轮回复流式结束或 TTS 播放结束后回到初始状态。

**理由**：timeline 有明确播放时长，适合自行恢复；表情和贴图更像回复期间的临时状态，需要跟随对话生命周期恢复，避免卡在临时表情。

**替代方案**：所有状态统一计时恢复。实现简单，但会在长 TTS 或慢流式输出时过早重置。

### D8: PSB 模型手动落盘 + 启动扫描

**选择**：不提供上传 API。用户将模型文件直接放入固定目录 `<nanobot-data>/desk_pets/psb/`；gateway 启动时扫描该目录，为尚无 `<文件名>.meta.json` 的 PSB 文件生成元数据。桌宠运行时的 TTS / 标签事件仍走 WebSocket（类似 `/ws/tha-events`）。

**理由**：第一版流程尽量简单：复制文件、重启 gateway 即可。无需配置路径、子目录或扫描接口。

**替代方案**：运行时热扫描 API——后续可加；每模型子目录——本期不需要。

## Risks / Trade-offs

- **[E-mote WebGL 兼容性]** 不同 PSB 版本/平台可能无法在 WebGL SDK 加载 → 新增模型时做 header/metadata 检查，展示“需要 ems/v3 或转换”的错误，并保存失败原因。
- **[模型文件体积和隐私]** 服务端保存模型会集中存储用户资产 → 模型目录使用 nanobot 数据目录而非包内静态资源；上传入口明确展示存储位置，删除模型时同时删除服务端文件与元数据。
- **[翻译质量不稳定]** LLM 可能误译变量语义 → 保存原文、中文、翻译时间和状态；设置页可显示原文 tooltip 并支持重试翻译。
- **[标签注入影响回复质量]** prompt 过长会占用上下文 → 只注入当前选中模型的可用类型、中文短描述和少量示例，不注入完整元数据。
- **[全屏鼠标追踪权限/性能]** 高频坐标转发可能造成渲染压力 → 主进程节流到 30 FPS 左右，窗口不可见或关闭时停止采集。
- **[多客户端资源加载]** Electron 渲染时可能需要从服务端拉取大资源 → 先使用受鉴权保护的资源 URL，必要时增加客户端缓存；缓存只作为加速，不作为模型真实来源。

## Migration Plan

1. 后端 schema 增加新的 `deskPet` 配置结构，不实现旧 `tha` 字段迁移。
2. 新增服务端 PSB 模型仓库、上传接口、资源接口、列表/删除/重扫/翻译接口和元数据持久化。
3. 设置 API 返回统一 `desk-pet` 负载；Electron types/API 适配新结构。
4. Electron store 仅保存窗口位置、尺寸、缩放、临时关闭等本地 UI 状态；模型列表、当前选中和初始状态以服务端配置/元数据为准。
5. 移植 PSB renderer，先支持从服务端模型资源加载并展示，再接入自动展示。
6. 接入 AI 标签注入、回复解析、TTS 音频事件和状态恢复。
7. 自定义别名作为后续能力，不进入本次实现。

## Open Questions

- 浏览器 WebUI 是否只提供设置/模型管理，还是后续也支持直接预览服务端 PSB 模型。
