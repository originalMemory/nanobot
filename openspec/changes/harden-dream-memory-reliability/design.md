## Context

`MemoryStore` 同时维护追加式 `history.jsonl`、历史计数器 `.cursor`、Dream 消费游标 `.dream_cursor` 和三个持久记忆文件。当前编号分配会优先信任 `.cursor`，Dream 提交说明则来自模型回复；定时任务与 `/dream` 又各自复制一套完成判断，因此损坏状态或模型误述会直接进入持久状态与审计记录。

本次吸收上游 0.3.0 的 Dream 可靠性设计，并保留 lover 现有的 Dream 调度、工具范围和 session 策略。考虑到上游随后已修正“完成但无变更的批次被永久重试”的问题，本实现以干净完成决定消费进度，以真实 diff 决定提交内容，避免照搬已知缺陷。

## Goals / Non-Goals

**Goals:**

- 保证历史编号和 Dream 消费游标不倒退、不接受负数。
- 让 Dream 直接看到当前持久记忆内容。
- 让 Dream 审计只描述三个持久记忆文件的真实变化。
- 让定时与手动 Dream 对完成、无变更、失败采用同一语义。
- 用回归测试覆盖损坏计数器、空变更、失败和真实 diff。

**Non-Goals:**

- 不改变 session replay、AutoCompact、archive 或缓存上限。
- 不改变 Dream 的调度频率、批大小、模型和工具权限。
- 不迁移现有历史文件名或存储格式。
- 不引入上游 0.3.0 之后更大范围的 Dream 输入保留改造。

## Decisions

### 1. 编号取持久计数器与历史事实的最大值

`.cursor` 仅在可解析为非负整数时参与计算。正常情况下取计数器和历史尾部有效游标的最大值再加一，避免过期计数器复用编号；历史已压缩而计数器领先时仍保持单调。仅当尾部损坏时扫描历史并恢复最大有效值，避免每次追加都退化成全文件扫描。

### 2. Dream 游标只单调前进

读取 `.dream_cursor` 时拒绝负数和损坏值，回退为 0；常规推进接口拒绝非法值，并忽略低于当前值的迟到写入。显式 `/dream-restore` 仍可连同记忆文件一起恢复旧游标，这是有意保留的灾备语义。

### 3. 当前记忆作为提示词事实，真实 diff 作为审计事实

提示词嵌入 `SOUL.md`、`USER.md`、`memory/MEMORY.md` 当前内容，每个文件设字符上限。提交摘要通过 Git HEAD 与工作树比较生成，只覆盖这三个文件，并显式排除 `.dream_cursor`。

不再把模型回复拼入提交说明。模型可以总结错，Git diff 才是 `/dream-log` 应展示的事实。

### 4. 完成状态决定消费，内容 diff 决定提交

只有 `_stop_reason == completed` 且本轮没有工具错误的 Dream 才推进消费游标；完成但无内容变更仍推进，避免同一无用批次阻塞后续历史。工具失败、执行异常或 Git 审计失败均不推进，即使留下了部分文件变化也保持可重试。

Git 未初始化时仍按完成状态推进。Git 已初始化但没有内容 diff 时不创建 Dream 提交；游标自身不构成有效内容变更。

### 5. 两个入口共享 MemoryStore 语义

定时 Dream 与 `/dream` 都调用同一组 `MemoryStore` helper：完成判断、内容 diff、提交消息与游标写入。入口只负责日志或用户反馈，避免再次分叉。

## Risks / Trade-offs

- [提示词增大] → 每个持久记忆文件最多嵌入 8,000 字符，防止异常文件无限膨胀。
- [diff 摘要过长] → 统一 diff 限制为 6,000 字符，但始终保留逐文件增删统计。
- [旧 `.dream_cursor` 为负数时会从头读取保留历史] → 这是安全回退；不会静默跳过尚未确认的输入。
- [失败 Dream 可能留下部分文件修改] → 不推进游标；真实 diff 会被保留并在后续运行中继续审视，不把失败误记为已消费。

## Migration Plan

无需数据迁移。新版本首次读取旧文件时会忽略非法负数；合法游标沿用。若需回滚代码，文件格式保持兼容。
