## 上游主要变更（v0.2.1）

- **RuntimeEventBus**（`nanobot/bus/`）：新增运行时事件总线，替代原来散落在 loop/webui 中的状态广播
- **WorkspaceScopeResolver**（`nanobot/security/workspace_access.py`、`workspace_policy.py`）：工作区沙箱隔离机制
- **turn_continuation**（`nanobot/session/turn_continuation.py`）：turn 续写逻辑，用于判断是否需要持久化 user message
- **GatewayServices**（`nanobot/webui/gateway_services.py`）：HTTP handler 抽象层，上游将 `websocket.py` 中的 HTTP 路由迁移到独立模块
- **NapCat 频道**（`nanobot/channels/napcat.py`）：新增 QQ NapCat 协议支持
- **Azure AAD 模式**：`azure_openai` provider 支持无 api_key 的 DefaultAzureCredential 认证
- **Session 管理优化**：`retain_recent_legal_suffix` 返回更精确的 `dropped, already_consolidated`
- **WebUI 重构**：新增 `ws_http.py`、`media_api.py`、`media_gateway.py`、`settings_routes.py` 等模块，activity timeline 组件群

## 合并后遗留技术债

| 编号 | 描述 | 优先级 | 状态 |
| ---- | ---- | ------ | ---- |
| TD-1 | `websocket.py` HTTP 路由（2282 行，88 个函数）未迁移到 `ws_http.py` + `GatewayServices` 模式 | 低 | ✅ 已修复（2026-06-05） |
| TD-2 | `transcript.py` 的 `augment_media_paths` 接口未对齐 upstream 的双回调参数（`augment_user_media` / `augment_assistant_media`） | 忽略 | 不修 |
| TD-3 | 合并残留了旧版 `HeartbeatService` 代码块（启动即 NameError 崩溃） | **紧急** | ✅ 已修复（2026-06-05） |

### TD-1 修复详情

**方案**：将 fork 全部 HTTP 路由提取到 `nanobot/webui/fork_http.py` 的 `ForkGatewayHTTPHandler`，`WebSocketChannel._dispatch_http` 仅负责 WS upgrade 检测并委托给该 handler。

**保留的 fork 独有路由**：`/api/inbox/thread`、`/api/avatar`、CLI Apps 管理、MCP presets、HMAC 媒体签名（含 byte-range / SVG CSP）、`model-configurations/update`、`network-safety/update` 等。

**兼容层**：`WebSocketChannel.__init__` 仍接受 `gateway=` 参数（从 `GatewayServices` 提取 `session_manager` / `workspace_path` / `tokens` / `workspaces`），并暴露 `channel.gateway` 代理对象供测试使用。

**测试**：`tests/channels/test_websocket_channel.py` 与 `test_websocket_media_route.py` 共 131 项全部通过。

**有意不实现 `GET /api/workspaces`**：上游该端点为 WebUI 工作区选择器提供默认 `project_path`、`restricted`/`full` 模式及 localhost 控件权限（能否改项目目录、能否开 full access）。本 fork 生产环境运行在 Docker 内，文件系统边界由镜像与 volume 挂载决定，不需要 WebUI 侧 per-chat 工作区沙箱；因此 `ForkGatewayHTTPHandler` 不注册此路由。合并后的 WebUI 仍会调用 `fetchWorkspaces()`，404 时被 catch 静默降级为 `workspaces = null`，工作区 picker 控件不可用，不影响对话主流程。WS 层的 `set_workspace_scope` / session metadata 仍保留（测试与协议兼容），生产不依赖。

### TD-1 分析（历史）

上游将 `WebSocketChannel._dispatch_http` 中的所有 HTTP 路由提取到 `nanobot/webui/ws_http.py`（494 行），并通过 `GatewayServices` 依赖注入。fork 有大量 upstream 没有的路由（`/api/inbox/thread`、`/api/avatar`、presence 追踪、token 管理、截图接口等），迁移需要：

1. 将 fork 独有路由也提取到独立模块
2. 扩展 `GatewayServices` 接口支持 fork 专有依赖
3. 同步改 `ChannelManager` 的初始化方式

**结论**：功能无 bug，仅是模块拆分问题。在 fork 路由稳定后再做，否则每次新增路由要改两处。

### TD-2 分析

upstream 拆分原因：assistant 媒体可能是进程本地的有时效签名 URL，重启后失效，需要独立的 re-sign hook。fork 的 `_sign_or_stage_media_path` 会在每次 replay 时重新签名，对 user 和 assistant 媒体行为一致，**不存在该 bug**，接口差异为纯形式问题。

**结论**：不修复。

### TD-3 修复详情

**根因**：合并时错误保留了旧版 `HeartbeatService`（`nanobot/heartbeat/service.py` 在上游已删除）的初始化代码块，包括：
- `on_heartbeat_execute` / `on_heartbeat_notify` 两个回调
- `heartbeat = HeartbeatService(...)` 实例化
- `run()` 中的 `await heartbeat.start()` 和 `heartbeat.stop()`

**修复**：移除上述全部代码（约 60 行）。heartbeat 功能已由 upstream 的 cron 系统任务路径承接（`on_cron_job` 中 `job.name == "heartbeat"` 分支 + `cron.register_system_job`），行为等价且更完善（增加了 `evaluate_response` 静默投递、session 注入等改进）。
